## Как собрать новую версию
1. Поднять `version` в `buildozer.spec` и `APP_VERSION` в `main.py` (одинаково; проверяется тестом).
2. Commit в `claude-fixes-2026-11-05` со словами `[build apk]` в описании → GitHub сам прогоняет проверки, собирает, подписывает, проверяет подпись и кладёт APK по постоянной ссылке. Около 3–13 минут (инструменты хранятся между сборками).
3. Без `[build apk]` сборка не запускается. Собирать только когда Алексей попросит.
4. В этом чате собрать APK нельзя (закрыт доступ к серверам Android) — только через GitHub.

## Что исправлено и добавлено (относительно 1.0 / сборки ChatGPT 1.1)
- Удаление заказа точно возвращает долг клиента, долг исполнителя, списание банера и прибыль.
- Оплата, переплата и обнуление переплаты не создают ложную прибыль.
- Служебные карточки (остаток, белый, чёрный банер) имеют постоянную роль; имя клиента («Черный Сергей», «Олег») на расчёты не влияет.
- Ошибка записи не закрывает приложение: всё откатывается, «Не сохранено, повторите».
- «Обнулить долг» исполнителя убирает историю в архив; связанного исполнителя нельзя удалить.
- «Сброс всех данных» сначала делает проверенную копию базы (папка backups/before_reset).
- Повреждённая база: отдельные копии, экран с объяснением вместо закрытия.
- Журнал операций (было → стало по каждой сумме) и перепроверка базы при каждом запуске — чтобы находить расхождения вроде Сашиного.
- Взаимозачёт: если человек и клиент, и исполнитель под одним именем (Дима Малевич), долги гасятся друг о друга автоматически, прибыль не меняется.
- Калькулятор: запятая = точка, двойная «Отмена шага» отменяет один шаг, база не перезаписывается на каждую цифру.
- На экране суммы в целых рублях (внутри считается до копейки); имя клиента и цвет рулона не пропадают при длинных числах.
- Окно рулона: поля парами, «СОХРАНИТЬ» над клавиатурой, клавиша ↵ сохраняет; исправлено закрытие приложения при сохранении рулона.
- «ВСЕ ЗАКАЗЫ»: у каждого дня кнопка «+ ДОБАВИТЬ» — дописать забытую позицию в заказ этого дня (обычный расчёт, дата = выбранный день, в расчёте жёлтая надпись «ДОПИСЬ В ЗАКАЗ ЗА …»). Не в APK пока.
- Карандаш у клиента → «ИСПРАВИТЬ ЗАКАЗЫ»: список по датам, нажать на позицию → поправить размер, кол-во, цену, цену исполнителю (у допобработки — сумму). Старая позиция отменяется и записывается новая с той же датой и на то же место; долг клиента, исполнителя, списание банера и прибыль пересчитываются. При сбое — всё как было. Не в APK пока.
- Расчёт: кнопка «+ ТАКСИ» рядом с допобработкой. Поля «Я ЗАПЛАТИЛ» и «КЛИЕНТУ» (пусто = столько же). В долг клиенту — сумма клиенту, в прибыль — разница (хранится как print_cost, mode='taxi', без исполнителя). Исправляется через «ИСПРАВИТЬ ЗАКАЗЫ». Работает и через «+ ДОБАВИТЬ» за прошлый день. Не в APK пока.
- Проверок: 106 (`python run_checks.py`, в Linux через `xvfb-run -a`).

## Правила работы с Алексеем
- Только по-русски, коротко, по одному шагу, со скриншотом для проверки.
- Ничего работающего не ломать и не удалять; перед изменением данных — резервная копия.
- Экраны компактные, без прокрутки, без огромных кнопок.
- APK собирать только по его просьбе.
- Не присылать в чат пароли и токены.
